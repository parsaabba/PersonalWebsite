Day 13

Packages & Project Structure

Understanding how Go organizes code into reusable components and managing dependencies with Go Modules.

1 The Anatomy of a Package

A package is a way to organize code, reuse functionality, and separate concerns. In Go, every .go file belongs to exactly one package, and one folder typically represents one package.

Visibility Rules

  • Exported (Public): Functions or variables starting with a Capital letter are accessible from other packages.
  • Private: Names starting with a lowercase letter are only visible within their own package.

2 Clean Folder Structure

go-project/
├── go.mod (Module info)
├── main.go (Entry point)
└── mathutils/
└── mathutils.go (Custom package code)

3 Go Modules (Required)

To use custom packages and manage dependencies, you must initialize a Go module in your project root.

go mod init go-project

This creates a go.mod file which tracks your module name and versions.

⚠️ Common Beginner Mistakes

  • Circular Imports: Go strictly forbids Package A importing Package B if Package B also imports Package A.
  • Forgetting Init: Trying to import local packages without running go mod init first.
